# 세이브브릿지 백엔드 최종 검증 보고 (동결본, 2026-10-19)

실제 데이터(`energy.csv`·`gas.csv`·`daily_temp.csv`·`savebridge.db`·`validation.csv`)로 전부 다시 돌렸다.
테스트 **52개 통과**, 실제 서버(uvicorn)에 전 엔드포인트 HTTP 호출 확인.

## 0. 동결 전 실행 순서 (이것만 하면 됨)

```
pip install -r requirements.txt
python load_data.py          # DB 재생성 (업로드한 DB와 사용량·기상 값 완전히 동일, data_source 컬럼만 추가)
python make_backup.py        # web/backup.json 재생성 (지표 18.7 / 0.655 확인)
pytest -q tests              # 52 passed 확인
uvicorn main:app --port 8000
```
Gemini 문장을 쓰려면 키 등록 후 `python explain.py --prewarm` → **그 다음** `python make_backup.py` (순서 중요).
키 없이도 템플릿 문장으로 정상 동작한다.

## 1. 지표 4개의 정체 — 전부 재현 완료

모두 **같은 모델**(일평균 사용량 ~ HDD+CDD 선형회귀, 앞 24행 학습 2020.01~2022.01 / 다음 12행 검증 2022.02~2023.02)이다.
다른 것은 "무엇을 예측하나"와 "지표를 무엇으로 재나" 둘뿐.

| 출처 | CV(RMSE) | R² | 12개월 합계 오차 | 정체 |
|---|---|---|---|---|
| 예선 제안서 | 14.9% | 0.616 | −4.96% | **전기만**, 지표를 월 합계로 계산 (`validation.csv` 예측값과 1kWh 이내 일치) |
| 제안서 7p | 15.0% | 0.661 | 약 −5% | **전기만**, 지표를 일평균으로 계산 (정확히 15.02%) |
| DB 직접 계산 / 현재 API | 18.7% | 0.655 | −5.7% | **전기+가스**, 일평균 — 시스템이 실제로 쓰는 모델 |
| 옛 backup.json | 19.4% | 0.626 | −7.6% | 현재 데이터·코드 어떤 조합으로도 재현 안 됨 → **폐기, 재생성함** |

참고: 가스만 따로 보면 CV 38.8%, R² 0.500. 기준온도를 바꿔도(14~24℃ 격자 탐색) 전체 기준 CV는 최저 18.58%.
→ **수치를 기준 안으로 넣으려고 검증 구간·데이터를 바꾸지 않았다.**

### 발표에 쓸 숫자 (권장)
- **판정용 대표 지표: 전기+가스 CV 18.7% · R² 0.655** — 정산이 전기+가스 합계에 대해 이뤄지므로 이게 시스템의 실제 성능.
- 전기 단독 15.0%(7p)는 "전기만 보면 기준선(15%)에 걸쳐 있다"는 보조 근거로만. **15.02%는 엄밀히 15% 초과** — "충족"이라고 말하지 말 것.
- 서사: "전기는 기온으로 잘 설명되지만, 2023년부터 가스가 운영 변화로 2배 가까이 늘어 합산 모델은 기준 미달 → 그래서 시스템이 금액을 확정하지 않고 RANGE·확인 중으로 처리한다." 이게 제안서의 '판정 보류' 규칙과 정확히 맞는다.
- ASHRAE G14 정의(n−p 분모, 월 합계)로 재면 전체 CV 20.6%, NMBE +7.6% → G14 기준이라고 말하지 말 것. 우리 지표는 "G14 기준값(15%)을 차용한 자체 산식".

## 2. 데이터 수

- 전기 **74개월**(2020.01~2026.04, 2021.10·2022.08 결측) — "75개월"은 틀린 숫자
- 가스 77개월(2020.01~2026.05). 2026.05 가스 50,964kWh는 전기 없음 → 합계 결측이라 자동 제외
- 병합 77행 → 합계 있는 74행 → 기상 JOIN 74행. 이상치 제거(중앙값 2배 초과) **0건**, 기온 결측일 **0일**
- 지표에 쓰는 건 74행 중 36행. 나머지 38행(2023.03~)은 지표에 안 들어감 → "74개월 전체 성능"이라고 말하지 말 것

## 3. 지표 산식 (baseline.py)

- a = 월 사용량 ÷ 그 달 일수, p = 예측 일평균, n = 12
- CV(RMSE) = √(Σ(a−p)²/n) ÷ ā × 100
- R² = 1 − Σ(a−p)² ÷ Σ(a−ā)²
- 12개월 합계 오차 = (Σ예측월합 − Σ실측월합) ÷ Σ실측월합 × 100 (음수 = 과소예측)
- HDD = max(0, 21.5 − 일평균기온), CDD = max(0, 일평균기온 − 16.0)의 월평균(℃/일)
- 판정: CV ≤ 15 그리고 R² ≥ 0.75 → CONFIRMED, 아니면 RANGE. `metric_checks`에 지표별 충족 여부 따로 표시

## 4. 금액 — 분배·정산 통일, 연료별 단가

`pricing.py` 한 곳에서 계산: `월 절감액 = 전기 실측 × 20% × 150원 + 가스 실측 × 20% × 80원`

| 항목 | 값 (2025.05~2026.04) |
|---|---|
| 전기 251,458 kWh × 20% × 150원 | 7,543,740원 |
| 가스 159,762 kWh × 20% × 80원 | 2,556,192원 |
| **연간 (월별 합)** | **10,099,932원** (90% 구간 7,955,522 ~ 12,244,340) |
| 정산 화면 같은 12개월 합 | 10,099,932원 — **일치 (테스트로 확인)** |
| 분배 70%·10년·투자 5천만 | 회수율 141%, 회수기간 7.1년, 필요 몫 49.5% |

- 이전 12,336,600원은 가스에 전기 단가를 붙인 값 → **발표 자료의 금액·회수율 수정 필요**
- 단가 2개 모두 **가정값** 표시. 확인처는 `pricing.py`의 `to_verify`
- 기저선이 아니라 실측 기준인 이유: 공사 전 시나리오는 "쓰는 양의 20% 절감". 기저선은 2023년 가스 변화 전 모델이라 최근 12개월을 약 19% 낮게 잡는다
- `python baseline.py`를 단독 실행하면 아직 12,336,600원이 찍힘(지윤언니 파일 내부 계산). **API·화면은 pricing.py 값**으로 덮어씀

## 5. 정산 상태 규칙 (main.settlement_status)

| 순서 | 조건 | 상태 |
|---|---|---|
| 1 | 정산 가능 달 0 + 데이터만 없음 | INSUFFICIENT_DATA 정산 불가 |
| 1 | 정산 가능 달 0 + 이상(±미공개) | REVIEW_REQUIRED 검토 필요 |
| 2 | 공사 전 (retrofit_ym 없음) | ESTIMATED 추정 |
| 3 | 정산 기간이 공사 완료월보다 앞 | ESTIMATED 추정 |
| 4 | 실측 기반 정산 미구현 (`ACTUAL_BASED_SETTLEMENT=False`) | PROVISIONAL 잠정 |
| 5 | 모델 CONFIRMED 아님 | PROVISIONAL 잠정 |
| 6 | 전부 통과 | VERIFIED 검증 완료 |

→ 현재 코드에서는 **어떤 입력으로도 VERIFIED가 나오지 않음** (전수 테스트).
실제 시연 분기: 2026Q1 추정 / 2023Q4 추정(10월만 확인 중) / 2023Q3 검토 필요 / 2026Q3 정산 불가.

## 6. 설명 문장 (explain.py)

- 데이터 없는 달 → "아직 공개되지 않아 금액을 계산하지 않았습니다" (LLM 호출 안 함)
- 공사 전 → "실제 절감액이 아니라 시뮬레이션" + CV·R² **둘 다** 미달이라고 명시
- 이상 월 → "원인이 확인되기 전까지 금액을 산출하지 않고 확인 중"
- LLM 차단: 없던 숫자, 숫자 바꿔치기(19.4→14.9), 판정 뒤집기(확정했/정산 완료/줄었습니다), 빈 응답, 시간 초과, 키 없음, 미설치 → 전부 템플릿으로 폴백 (가짜 Gemini로 테스트)
- `action` 값 추가: "데이터 없음", "시뮬레이션" — **프론트가 action별 색을 쓰면 매핑 추가**

## 7. 절감 대책·온실가스 (measures.py)

- 개별 = 연료 사용량 × 절감률, 같은 연료 복수 = 1 − Π(1 − rᵢ) (손계산 일치)
- 2025년 기준 전체 61,815 ~ 107,993 kWh (단순 합 67,895 ~ 127,895, 차이 = 중복 보정)
- CO₂ 15,733 ~ 28,307 kg
- 절감률 4개 `basis: assumed`(시나리오 가정값), 배출계수 2개 `verified: False` — **출처 원문 미확인 상태 그대로**
- 가스 0.2020 = IPCC 기본값 56,100 kgCO₂/TJ × 3.6×10⁻⁶ TJ/kWh (발열량 기준 미확인)

## 8. 건물 2 (양평 블룸비스타)

- 사용량은 건물 1을 **배율 없이 그대로 복사**한 가상 데이터 (값 비교로 확인)
- `building.data_source` + 모든 관련 API에 `data_origin` (`is_simulated: true`, `label: "가상 데이터"`)
- 메인 시연·주소 불일치 fallback 모두 건물 1. **프론트에서 is_simulated면 배지 표시 필요**
